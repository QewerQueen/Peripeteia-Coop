# Solo testing

Один из главных принципов проекта: **любую сетевую функцию можно проверить
одному, без второго ПК и без друга.**

Сейчас реализован прототип M2: два процесса соединяются по UDP, создают
удалённого игрока из модели Марии и синхронизируют позицию/поворот с частотой
30 Гц. Модель второго игрока пока статична: данные анимации уже входят в пакет,
но клон её не проигрывает (см. ограничения ниже).

## 1. Два процесса на одном ПК

```powershell
.\scripts\run-two.ps1
```

Скрипт запускает:

- **host** — `-coop-host -coop-port 7777 -coop-name Host`, окно 1280×720;
- **client** — `-coop-connect 127.0.0.1 -coop-port 7777 -coop-name Client`,
  окно 960×540.

У каждого свой Unity-лог:

```
local/logs/host.log
local/logs/client.log
```

BepInEx пишет по одному файлу на процесс (`BepInEx/LogOutput.log` и
`LogOutput.1.log`). В логах ищи строки:

```
[net] role=Host ...
[net] Peer connected: id=1 ...
[avatar] cloned player model: renderers=...
[net] ... poses: 1@(x,y,z)
```

В кооп-режиме плагин принудительно включает
`Application.runInBackground = true`, поэтому неактивное окно продолжает
симулировать мир. Без этого host «замирал» бы, пока ты переключаешься на
client. При обычном одиночном запуске без `-coop-*` эта настройка не меняется.

Хост начинает слушать UDP сразу при загрузке плагина, но загрузка главного меню
может занять несколько секунд. Поэтому клиент повторяет попытки подключения
до 120 раз с интервалом 0,5 с (вместо стандартных 10 раз / ~5 с), а таймаут
соединения увеличен до 20 секунд. Без этого клиент иногда сдавался с
`ConnectionFailed` раньше, чем второй процесс успевал принять подключение.

Сеть тикает через отдельный `CoopRunner` (MonoBehaviour от BepInEx), а не
через `PlayerMovement.Update`. Это важно: во время загрузки уровня
`PlayerMovement.Update` может не вызываться, и раньше это задерживало
handshake и рвало соединение.

## 2. Как увидеть второго игрока

1. Запусти `.\scripts\run-two.ps1`.
2. В host начни игру (New Game / Load).
3. Переключись на client (Alt+Tab) и загрузи **тот же** сейв или начни новую
   игру в том же уровне.
4. Вернись в host. Второй игрок — клон Марии, который двигается по сети.
5. Если оба стоят на одном `PlayerStart`, они появились в одной точке.
   Двигайся/отойди, чтобы увидеть друг друга.

Сейчас удалённый аватар — статичная копия модели. Он перемещается и
поворачивается по сети, но не проигрывает ходьбу/прыжок/приседание. Анимация
будет добавлена отдельным этапом: сохранять `Animator` на клоне нельзя —
в тесте это останавливало главный поток Unity и рвало соединение.

## 3. Автопилот

```powershell
.\scripts\run-two.ps1 -AutoPilot
```

Client автоматически двигается по маленькому кругу (`PlayerMovement.TeleportPlayer`),
а host получает его позицию. Это позволяет проверять репликацию, не трогая
второе окно.

Планируемые режимы:

- `--coop-autopilot` — уже есть (debug);
- `--coop-loopback` — фальшивый клиент внутри процесса host;
- `--coop-headless` — сервер без рендера (`-batchmode -nographics`).

## 4. Сохранения

Оба процесса используют один каталог:

```
%USERPROFILE%\AppData\LocalLow\Ninth Exodus\Peripeteia
```

`run-two.ps1` перед запуском копирует `EASaves` в
`local/saves_backup/<дата-время>/`. Это защита от того, что client
перезапишет прогресс host'а.

Дополнительно клиент блокирует запись сохранений на уровне Harmony:
`SaveHandler.RequestSave`, `SaveHandler.ProcessRequestedSave` и
`SaveHandler.AutosaveOnLevelStart` возвращают `false`. Загрузка при этом
работает. В логе будут строки `[save] Client blocked ...`.

Если нужно разрешить клиенту сохраняться, задай в
`BepInEx/config/peripeteia.coop.cfg`:

```ini
[Client]
BlockSaves = false
```

Не отключай это при обычной игре вдвоём: у клиента и хоста общий каталог
`EASaves`, и клиент затрёт прогресс хоста.

## 5. Производительность

Два экземпляра Peripeteia на одной видеокарте — нормально для PSX-стиля, но
следи за VRAM. Если тяжело:

- уменьши разрешение client-окна (`-ClientWidth 800 -ClientHeight 450`);
- снизь настройки графики в client;
- позже попробуем `-nographics` для client.

## 6. Ограничения текущего прототипа

- Синхронизируются только позиция и поворот (30 Гц, unreliable UDP).
- Данные анимации передаются в пакете, но визуально не применяются.
- Нет синхронизации оружия, стрельбы, дверей, AI, инвентаря,
  диалогов, квестов и переходов между сценами.
- Удалённый аватар — клон локальной модели; скины/одежда второго игрока
  пока не передаются.
- Нет реконнекта и проверки версий мода/игры.
- Оба процесса должны вручную загрузить один и тот же уровень.

Эти ограничения — следующие этапы, а не баги текущего прототипа.
